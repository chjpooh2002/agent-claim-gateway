# 001. 교환을 넣는다면 클레임 하나인가, 반품 + 재배송 두 흐름인가

- 상태: 결정됨
- 날짜: 2026-11-08
- 관련 이슈: #1

## 맥락
교환은 범위 밖이다(기획서 4절). 하지만 "넣는다면 어떻게 설계하겠는가"에 답할 수 있어야 하고, 그 답이 지금 클레임 모델이 어디까지 버티는지를 보여준다.

따라가 본 장면: 셔츠 2장(M) 중 1장을 L로 교환 요청 → 몰이 회수·검수 → 오염 발견으로 검수 거절.

이 장면에서 드러난 문제:
- 클레임 행이 무엇을 기준으로 생기는지 정의돼 있지 않았다.
- 지금 상태 기계(7절 그림)는 "몰에 요청을 보내고 결과를 받는" 왕복 하나만 다룬다. 교환의 반품은 몰이 접수한 뒤에도 회수 → 검수 → 결과로 며칠이 이어진다.
- 교환의 반품은 환불하면 안 되는데, 반품 행이 자기가 교환의 일부인지 알 방법이 없었다.

## 선택지
1. 안 A — 클레임 하나: 유형에 "교환"을 추가하고, 한 행이 반품부터 재배송까지 모든 단계를 담는다.
2. 안 B — 반품 + 재배송 두 행: 반품 행과 재배송 행을 따로 두고 서로 연결한다.

## 결정
**안 B.** 기준은 "몰에 보내는 요청 하나 = 클레임 행 하나"다.

- **행 기준**: 멱등 키 하나, 외부클레임번호 하나, 상태 전이 하나가 한 행에 대응한다. 지금 클레임 엔티티(기획서 6절)의 필드 구성이 이미 이 기준을 전제한다.
- **재배송 행 생성 시점**: 반품 행의 검수가 통과한 뒤에 만든다. 요청 시점에 미리 만들면 며칠 동안 "접수됨"으로 머물고, 아웃박스 작업자가 그 행을 꺼내 몰에 보내 버릴 수 있다.
- **연결**: 재배송 행에 원래 반품 행의 ID를 둔다. 에이전트는 반품 행에서 시작해 그 ID를 가리키는 재배송 행을 찾아 진행 상황을 이어 본다.
- **반품 행의 교환 표시**: 반품 행에 `교환용반품` 칼럼을 둔다. 동작("환불 불가")이 아니라 목적을 담는다. 이 표시 하나로 세 가지 동작이 갈린다: 환불하지 않기, 검수 통과 시 재배송 행 만들기, 에이전트가 "교환 진행 중"으로 안내하기. 칼럼에 동작 하나만 담으면 나머지 두 동작은 각자 그 칼럼을 다르게 해석해야 한다.
- **검수 결과**: 반품 행에 `검수상태`(대기 / 통과 / 거절)와 `거절사유`를 둔다. 일반 반품도 몰이 검수한 뒤에 환불하므로 교환 전용 칼럼이 아니다.
- **"완료"의 뜻**: 몰이 요청을 받아들였다는 뜻이다. 업무의 최종 종결은 검수상태로 따로 본다. 완료를 "최종 종결"로 두면 반품 행이 며칠 동안 "외부처리중"에 머물러 9절의 "시간 초과면 재조회" 규칙과 충돌한다.

## 버린 안과 이유
- 안 A: 한 행이 몰 요청 두 개(반품, 재배송)를 담게 된다. 그러면 멱등 키와 외부클레임번호가 행당 둘씩 필요하다. 상태도 두 흐름의 조합이 돼서 설계가 두 배가 된다(기획서 4절). 정한 행 기준과도 맞지 않는다.

## 관련 CS 지식
- 도메인 모델링: 엔티티 하나의 경계를 어디에 둘지("몰 요청 하나")
- 상태 기계: 요청 왕복 상태와 그 뒤에 이어지는 업무 진행을 분리
- 장기 실행 프로세스: 응답을 받은 뒤 며칠 뒤에 도착하는 결과를 다루는 방식

## 다른 판단으로 넘긴 것
- 몰이 검수 결과를 우리에게 알려주는 **수신 경로**(조회 대 통보), 신호 유실 → 판단 7 (#7)
- 같은 신호가 두 번 오는 경우 → 판단 5 (#5)
- 몰마다 교환 방식이 다르다. 검수 통과 후 몰이 자동으로 재배송하면 우리가 보내는 요청이 없어 1행이다. 재배송을 따로 요청해야 하면 2행이다. 이 차이를 어댑터 안에 가둘 수 있는지 → 판단 3 (#3)
- 반품 행이 "완료"인데 검수가 "대기"일 때 에이전트가 무엇이라고 안내할지 → 판단 11 (#11)
- 기획서 6절 클레임 상태 목록(6개)과 7절 상태 전이 그림(7개, "외부 상태 재조회" 포함)이 어긋난다 → 기획서 정리 시 맞춘다

## 결정을 뒤집을 조건
- 연동할 몰 대부분이 교환을 요청 하나로 처리하는 전용 API를 제공하면, 행 기준에 따라 교환이 한 행이 된다. 그때 안 A를 다시 본다.
- 클레임 상태 전이에 검수 같은 후속 단계가 계속 늘어나면, 클레임 위에 업무 단위 엔티티(교환 묶음 등)를 두는 구조를 검토한다.

## 예상 면접 질문
- 교환은 왜 뺐나요? 넣는다면 어떻게 설계하겠어요? (기획서 13절 2번)
- 클레임 행 하나의 기준은 무엇인가요? 그 기준으로 교환은 몇 행이 되나요?
- 반품이 "완료"됐는데 검수에서 거절되면 어떻게 표현하나요?
